\section{Related Work}
\label{sec:related}

Automating software test generation from natural language requirements has long been a key goal in automated software engineering. This section organizes prior research into three main themes and positions our work within the existing literature.

\subsection{BDD Scenario and Step Definition Generation}
Early approaches to BDD test automation relied on heuristic Natural Language Processing (NLP) or rule-based grammars to extract action verbs and entities from user stories. While effective in constrained environments, these systems lacked flexibility when handling ambiguous, free-form requirement texts.

With the emergence of Large Language Models (LLMs), recent work has examined model capabilities for BDD artifact synthesis. Fernandes et al.~\cite{fernandes2024} evaluated commercial LLMs (GPT-3.5 and Gemini) for generating Gherkin scenarios, finding that while commercial APIs produce valid Gherkin syntax, prompt refinement is required to capture edge-case business logic. In a separate study, Tesfalidet~\cite{tesfalidet2025} evaluated step definition code generation using GPT-4, observing high syntactic accuracy but frequent parameter naming divergence from existing test codebases.

\textit{Positioning Statement:} Unlike previous studies that evaluate scenario generation or step definition synthesis in isolation, our work evaluates the *joint* end-to-end generation of both Gherkin scenarios and Behave Python step definitions within a single inference pipeline.

\subsection{Prompt Engineering Strategies in Automated Software Testing}
Prompt engineering strategy significantly influences LLM performance on software engineering tasks. Zero-shot prompting evaluates baseline model knowledge without context, whereas Few-shot prompting guides model formatting and logic through in-context exemplars. Chain-of-Thought (CoT) prompting introduces intermediate reasoning steps to break down complex tasks.

In software test generation, researchers have compared these prompting techniques to optimize code correctness and coverage. However, findings remain mixed regarding whether CoT prompting consistently improves code synthesis, as intermediate reasoning can introduce formatting noise that complicates automated post-processing.

\textit{Positioning Statement:} However, existing studies have not systematically quantified the trade-offs between Zero-Shot, Few-Shot, and CoT prompting for joint multi-artifact BDD generation under strict statistical hypothesis testing.

\subsection{Foundation Models in Software Test Automation}
Recent developments in foundation models have led to the deployment of highly capable models such as OpenAI's GPT-4o. While GPT-4o exhibits strong reasoning and code synthesis across general benchmarks, empirical evaluations regarding its comparative prompt sensitivity for domain-specific testing formalisms (such as BDD Gherkin and Behave step definitions) remain limited.

Rathnayake et al.~\cite{rathnayake2026} established a public benchmark dataset of user stories paired with expert Gherkin scenarios, providing a standardized foundation for empirical LLM benchmarking.

\textit{Positioning Statement:} Unlike prior work evaluating earlier model generations, our study systematically benchmarks \texttt{GPT-4o} across 500 industrial user stories, quantifying the exact impact of prompt engineering techniques on semantic similarity, Gherkin syntax validation, Python AST parse rates, and structural content statistics.
